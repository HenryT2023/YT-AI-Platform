# 严田文明智慧工作台 V1

本地可运行的文化知识、出处问答、传统手工木刻稿样和工艺师审阅软件。
本地整合版已经挂载到原严田OS的 `/studio/#qa`，由Core创建唯一CultureService，
与原知识接口、NPC和只读检索共用既有文化SQLite。原件、运行库和导入包不随源码分发。
整合启动方法见[本地整合说明](../../docs/local-os-integration.md)。

## 启动

原OS集成使用Python 3.11+。下面是独立验证模式，使用另一个本地目录和端口；
它不接替OS的既有文化库，也不启动原平台的PostgreSQL、Redis、迁移或IoT网关。

```sh
python3 -m pip install -r requirements.txt
python3 server.py --data-dir ./local-data --port 8795
```

独立模式浏览器访问 http://127.0.0.1:8795 。服务只绑定本机回环地址；未提供多人登录、
角色身份核验或公开部署配置。不要将该端口代理到公网或共享网络。

## 能运行的流程

1. 登记来源标题、链接或本地引用、地域/用途范围；录入文化知识与原件位置。
2. 知识状态区分草稿、已核来源、已审核、争议与退役。已核来源仅表示发布内容核对，
   不证明严田具体对象、工艺师身份或商用/训练许可。
3. 提问并查看资料摘录、来源链接、段落定位、知识版本与范围。证据不足时返回缺口。
4. 创建原创几何、叶形或波纹的木刻设计练习稿，编辑文字、尺寸、用途与镜像选择，
   预览、保存不可覆盖的版本并下载SVG；也可提交受严格清洗的SVG源文件。
5. 工艺师以本地申报岗位提交修改意见或审阅结论，绑定当前稿样版本。编辑后旧批准失效，
   历史意见保留；印版用途须先确认镜像，原始练习图案不冒充传统纹样。
6. 审阅反馈进入待复核的学习候选，训练用途保持未知；导出研究与设计记录。

## 问答与模型状态

首版默认使用本地中文检索和证据摘录，无外部模型调用、密钥或静默沙箱回答。
界面与响应均标记 `extractive`，不把资料检索称为已训练的严田大模型。
区域材料不能独自回答严田具体起源、年代或传承身份；项目需求记录不能作为村史证据。
后续生成式模型应沿现有Orchestrator的版本化适配接口接入，并独立评测。

## 首批资料

`seed.json`只含一份公开资料的短摘要和用户已确认的首期项目要求。公开资料来自
[中国非物质文化遗产网《徽州三雕》](https://www.ihchina.cn/news_1_details/11243.html)，
限定徽州区域范围、内部研究用途；不包含私人原件、村民/客人资料或未经验证的严田故事。
知识条目是起始材料，用户可补充有权使用的真实严田资料并保留原件定位。

机器接口关闭，任何提交请求都应被拒绝，不产生queued任务、设备回执或G-code。
本软件不产生真实制作、试印、成品合格、销售或到账记录。稿样是待专业审图的设计文件。

## 数据与测试

SQLite存储在指定的数据目录。保留设计和知识历史版本；退出并重新启动后记录仍在。
界面的导出功能生成可回查的JSON。本地受控导入工具 `ingest.py` 已实现：
核对指定原件哈希和段落原文，幂等写入来源、知识、选段、争议/缺口及批次回执。
导入记载保持待核，不经编辑或verify升格；原件路径不存入或返回API。
完整契约见 `API_CONTRACT.md`。恢复向导和生产导入不在本版范围。

```sh
python3 -m pytest tests -q
```

测试使用临时数据库。浏览器验收使用另一个隔离数据目录，测试审阅不写入用户工作库。
`API_CONTRACT.md`为本地首版契约，机器字段和生产适配不表示已实现。
