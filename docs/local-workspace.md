# 严田分层工作空间

本版先落实第一层。打开 `/` 或 `/workspace`，输入一句话，添加照片或附件，生成住宿＋严田 CREATE 文化体验的运营方案。首页只保留这一项主任务；房态、目录、订单与文化知识收在辅助入口。

## 三层顺序

1. **运营方案**：目标与日期、客群假设、住宿和一至两项 CREATE 体验候选、渠道安排、执行动作、所需材料、依据和待核清单。
2. **视频脚本**：确认第一层的精确版本后，另行点击交给第二层；复用现有 `/growth` 的脚本、分镜、素材与字幕。保存并确认脚本分镜后，可显式生成本地视频、预览和下载；交接本身只建任务。
3. **乡村管理模型**：后续独立建设。现有文化检索、木刻审阅和经营台账属于可复用基础，本版不宣称训练或运行了严田专属大模型。

## 本地输入与资料

支持 JPG、PNG、WebP、TXT、MD、CSV、XLSX、DOCX、PDF，单份最大10MiB。照片仅作参考，可提取其中的文字线索；当前未接入图片视觉理解。文档提取限定为主题与日期提示，不把原始客户记录带入方案。解析失败会提示，原输入可继续修改。附件只保存在本地数据目录，不进入程序ZIP。

复用 `yantian-growth-context.json` 的既有 CREATE 摘要和 `rs_*` 的房态来源，不建立第二份文化库。用户确认的“住宿＋文化体验是现成产品”与各条目录的具体交付条件分别保留。380元为此前淡季住宿参考，不能推算套餐报价；来源填0不是核清的可售库存。

## 版本与边界

方案生成后为待确认。相同输入和来源复用同一版本；修改后生成不可变的新版本，旧确认不继承。确认仅采用策划方向，不能代替核房、报价、素材权利或现场交付核验。来源、附件内容或既有配置变化后，需要重新生成和确认。

第一层不写 `op_*` 经营台账，不自动生成 `gr_*` 视频包。第二层交接与本地回执分别持久化，重试复用同一任务；不存在跨步骤原子事务的承诺。模型、平台发布、银行支付和机器适配均未连接。

## 本地验收

使用临时SQLite验证文本/附件、版本、确认、来源变化和第二层交接。本地方案确认与成片确认只在用户明确采用相应版本时登记；隔离测试不写用户经营台账。桌面与手机检查主要输入、结果和返回第一层入口。启动、停止和换机仍使用 `docs/local-os-integration.md`。
