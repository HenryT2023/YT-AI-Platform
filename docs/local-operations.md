# 严田 OS · 住宿与体验运营

入口为 `/operations`，从原 OS 首页进入；本地独立站预览为 `/stay`。
此模块随原 Next 游客应用及 Core 启动，没有新增独立 OS。

## 初始资料与数据边界

初始配置仅来自本次用户陈述：严田庄园、30 间自有房、淡季住宿参考价 380 元/间夜、
小红书和抖音尚未开通。它们是管理者提供的信息，尚未由房表或流水独立核实。
未生成房号、已入住记录、收入、客户、工艺师、可售体验或平台账号。
30 是房源总量上限，不是某一天可售量；380 是参考，不自动成为每一笔订单的价格。

文化知识、出处问答、稿样及精确版本审阅继续使用原有 CultureService 与同一文化 SQLite。
运营模块通过工作室入口复用这些功能；业务账本不把销售文案写回文化事实，也不复制第二份知识库。
木刻软件可用不代表已有工艺师、场次或对外接待能力。

## 首次使用顺序

1. 在“房源房态”填写实际房号、名称和房型；未建档的房间不计入可售。
2. 选择入住/离店日期查房。离店日不占房；维修、业主自用等用封房登记。
3. 在“住宿与体验”建立住宿商品。体验/套餐先存草稿，确认负责人、时长后才能启用；
   场次另填时间、容量和交付确认，房间与体验容量分别管理。
4. 在“渠道与内容”登记独立站、小红书、抖音或其他渠道的咨询线索、来源码与内部内容草稿。
   文案使用已确认事实；文化解说先到文明工作室查来源。
5. 在“订单台账”选择商品、房间/场次，输入实际人工报价。暂留默认30分钟，这是本软件的可调整规则，
   不是庄园已经采用的销售承诺。重复日期占房、封房和超容量会被拒绝。
6. 手工登记实际收到的款项及凭证编号；它只是本地台账，不是向银行卡扣款或平台验款。
   足额登记后确认，净登记收款仍大于零的未足额订单保留库存，需管理者跟进；全额退款使净额归零后，未确认暂留可在到期时释放。
7. 实际履约后标记完成，提前登记会被拒绝；履约后的原日期/场次占用记录继续保留。
   取消释放库存；实际退款后另登记退款凭证，不把取消当作自动退款。
   套餐体验按北京时间须在入住日至离店日之间（允许离店日），已过场次不能新订。

独立站预览展示已启用商品，并可保存日期与人数咨询。咨询不会自动占房、报价、收款或确认订单。
带 `?source=来源码` 的本地预览链接可将来源码记入咨询记录；它不证明平台已产生流量。
没有真实流水时收入显示未登记；人工登记金额不等于银行或平台对账结论。

## 本地保存和恢复

运营记录默认保存到启动 `--state-dir` 中的 `operations.sqlite3`，可通过 `--operations-db` 显式指定。
运营SQLite中的房间、场次、占用、订单、收退款使用同一事务；不会声称和文化库或PostgreSQL跨库原子提交。
原文化文件路径不变。停止服务不会清空记录。程序ZIP不包含任何运行库。

运营页可导出业务JSON；文化资料在工作室另行导出。本版无导入恢复向导。
需要完整本地备份时先停止本整合版，再备份运营SQLite及既有文化SQLite，启动时继续指定相同路径。
多人权限、公开网络接待、平台库存同步、真实支付对账与外部消息尚未实现。

## 验证方法

只使用 `services/core-backend/local_tests/test_operations.py` 中的临时库和隔离HTTP验收。
不得运行原 Core 的破坏性测试 fixture，也不得向用户工作库塞入测试订单。
机器接口继续关闭；本模块没有设备指令入口。
# 最新房态来源观察

`/operations#room-status` 展示同事房态表的脱敏来源快照与逐日房型记录。导入接口为 `POST /api/local-os/room-status/imports`，只接收受控JSON契约，不读取任意本机路径。相同来源和解析返回NO_CHANGE；新解析保存历史版本。

当前来源表列双床18、大床10，共28间；持有人此前声明30间，差2间待核。2026年依据持有人“接下来11月和12月”补充，不写成表内年份。空白保留未知，黄色保留未确认，粉色预订保留业务状态未核，0预订只代表来源记录。缺失日期、业务截至时间、房号、停用和其他渠道占用、报价与收款各自待核。

房态观察保存在同一运营SQLite的rs_*表，不改op_*房源、封房、订单或资金流水。正式可售查询仍需实际建档与库存约束，不能直接导入房型汇总后忽略未知日期。

日期机会只由所选房型明确填0的连续日期生成，含末日、按月分段；不是已核可售窗口。日期卡带房态快照和窗口ID进入内容获客。未知、未确认和未覆盖日期不自动变成零预订机会。
